### **Решение**
Архитектурное решение основано на расширении существующей инфраструктуры банка с добавлением специализированных кредитных микросервисов.

#### Ключевые архитектурные принципы:
1. **Переиспользование существующих систем**: Максимальное использование кредитного конвейера Camunda и системы скоринга
2. **Event-Driven Architecture**: Асинхронная обработка через Kafka для развязки компонентов
3. **API-First подход**: REST API для всех интеграций с внешними системами
4. **Микросервисная архитектура**: Изоляция кредитного функционала в отдельные сервисы

#### Основные компоненты решения:

**Новые микросервисы:**
- **Credit Application Service**: Управление жизненным циклом кредитных заявок, валидация данных, интеграция с конвейером
- **Pre-approval Service**: Расчет предодобренных кредитных предложений на основе скоринга и данных клиента
- **BKI Integration Service**: Интеграция с Бюро кредитных историй, обработка согласий на проверку
- **Credit Notification Service**: Уведомления клиентов о статусе кредитных заявок через СМС и email

**Расширения существующих систем:**
- **Credit Module в интернет-банке**: Новый модуль на ASP.NET MVC для отображения предодобренных предложений
- **Credit Landing на сайте**: React.js компонент для подачи кредитных заявок новыми клиентами
- **Credit API Gateway**: Java Spring Boot gateway для маршрутизации кредитных запросов

**Инфраструктурные компоненты:**
- **Credit Database (MS SQL)**: Хранение кредитных заявок, предодобрений, логов интеграций
- **Redis Cache**: Кэширование предодобренных предложений и скоринговых данных
- **Kafka Credit Topics**: События кредитных процессов (application.submitted, decision.made, notification.sent)

#### Диаграммы C4:

**Контекстная диаграмма:**
- Показывает взаимодействие клиентов (существующих и новых) с системой кредитования
- Интеграции с внешними системами: БКИ, АБС, кредитный конвейер, система скоринга
- Роли персонала: кредитные специалисты, операторы кол-центра

**Диаграмма контейнеров:**
- Детализация микросервисов и их взаимодействий
- API Gateway как единая точка входа для кредитных операций
- Kafka как центральная шина событий для асинхронной обработки
- Интеграции с legacy системами через REST API и batch-процессы

#### Технологический стек:
- **Backend Services**: Java Spring Boot (новые микросервисы)
- **Frontend**: React.js (сайт), ASP.NET MVC (интернет-банк)
- **Database**: MS SQL Server (основные данные), Redis (кэш)
- **Message Queue**: Apache Kafka
- **Workflow Engine**: Camunda BPM (существующий кредитный конвейер)
- **External APIs**: БКИ REST API, Телеком REST API

#### Логика принятия архитектурных решений:

**Использование существующего кредитного конвейера:**
- Соответствие требованию +R1
- Минимизация рисков изменения проверенных бизнес-процессов
- Переиспользование накопленных знаний и правил кредитования
- Снижение времени разработки и тестирования

**Микросервисная архитектура для новых компонентов:**
- Соответствие требованию +R3
- Изоляция кредитного функционала от существующих систем
- Возможность независимого масштабирования под нагрузку
- Упрощение deployment и rollback изменений

**Асинхронная обработка через Kafka:**
- Соответствие требованию +R4
- Отказоустойчивость при высоких нагрузках (NFR3)
- Развязка микросервисов для повышения надежности
- Возможность replay событий при сбоях

**Интеграция с БКИ через отдельный сервис:**
- Соответствие требованию +R6
- Централизованное управление лимитами запросов к БКИ
- Обработка согласий клиентов в соответствии с требованиями ЦБ
- Circuit Breaker pattern для обработки недоступности БКИ

### **Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

#### Альтернатива 1: Монолитное расширение интернет-банка
**Описание**: Добавление всего кредитного функционала непосредственно в существующий монолит интернет-банка без выделения микросервисов.

**Преимущества**:
- Простота реализации и deployment
- Использование существующей инфраструктуры без изменений
- Единая точка управления и мониторинга
- Отсутствие сетевых задержек между компонентами

**Недостатки**:
- Нарушение требования микросервисной архитектуры (+R3)
- Сложность независимого масштабирования кредитного функционала
- Риск влияния на стабильность существующего интернет-банка
- Ограничения в выборе технологий (привязка к ASP.NET)

#### Альтернатива 2: Полная замена кредитного конвейера
**Описание**: Создание нового кредитного конвейера с нуля на современных технологиях вместо использования существующего Camunda.

**Преимущества**:
- Современная архитектура без технического долга
- Полный контроль над бизнес-процессами кредитования
- Возможность оптимизации под онлайн-каналы
- Отсутствие ограничений legacy системы

**Недостатки**:
- Прямое нарушение требования +R1
- Высокие риски потери проверенных бизнес-правил
- Значительные временные и финансовые затраты
- Необходимость полного регрессионного тестирования кредитных процессов

#### Альтернатива 3: Синхронная интеграция без очередей
**Описание**: Использование только синхронных REST API для всех интеграций без внедрения Kafka.

**Преимущества**:
- Простота архитектуры и отладки
- Прямые ответы клиентам без задержек
- Меньше инфраструктурных компонентов
- Легче обеспечить консистентность данных

**Недостатки**:
- Нарушение требования асинхронной обработки (+R4)
- Низкая отказоустойчивость при сбоях внешних систем
- Сложности обработки пиковых нагрузок (NFR3)
- Каскадные сбои при недоступности одного из сервисов

**Недостатки, ограничения, риски**

#### Недостатки выбранного решения:

1. **Архитектурная сложность**: Увеличение количества компонентов усложняет эксплуатацию и мониторинг системы
2. **Eventual Consistency**: Асинхронная обработка через Kafka может привести к временной несогласованности данных
3. **Сетевые задержки**: Множественные API-вызовы между микросервисами могут увеличить общее время отклика
4. **Зависимость от внешних сервисов**: БКИ может быть недоступно, что заблокирует обработку заявок новых клиентов
5. **Операционные накладные расходы**: Необходимость мониторинга и управления множественными сервисами

#### Ограничения:

1. **Лимиты БКИ**: API Бюро кредитных историй может иметь ограничения на количество запросов в минуту/час
2. **Batch-интеграция с АБС**: Ограничение синхронизации кредитных данных до одного раза в день
3. **Производительность скоринга**: Существующая система скоринга может не справляться с увеличенной нагрузкой
4. **Регуляторные требования**: Жесткие требования ЦБ по процедурам кредитования и защите персональных данных
5. **Legacy ограничения**: Кредитный конвейер Camunda может иметь технические ограничения для новых интеграций

#### Риски:

1. **Технический риск**: Сложность интеграции с legacy системами может привести к задержкам проекта
2. **Операционный риск**: Сбои в критичных интеграциях (БКИ, скоринг) могут остановить кредитные процессы
3. **Производительностный риск**: Система может не обеспечить требуемое время отклика (NFR1, NFR2) при высоких нагрузках
4. **Комплаенс риск**: Нарушение требований ЦБ по кредитованию может привести к регуляторным штрафам
5. **Безопасностный риск**: Обработка кредитных данных и интеграция с БКИ требует повышенных мер информационной безопасности
6. **Бизнес риск**: Неточности в скоринге или сбои автоматизации могут привести к неправильным кредитным решениям

#### Меры по снижению рисков:

1. **Поэтапное внедрение**: Начало с ограниченного набора кредитных продуктов и постепенное расширение
2. **Circuit Breaker Pattern**: Реализация автоматического переключения на ручную обработку при сбоях внешних систем
3. **Comprehensive Testing**: Полное нагрузочное и интеграционное тестирование перед production
4. **Monitoring & Alerting**: Детальный мониторинг всех компонентов с настройкой алертов на критичные метрики
5. **Backup Procedures**: Процедуры ручной обработки заявок при недоступности автоматических систем
6. **Security Audit**: Регулярный аудит информационной безопасности и соответствия требованиям ЦБ
7. **Rate Limiting**: Контроль нагрузки на внешние системы для предотвращения превышения лимитов
